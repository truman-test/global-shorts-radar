# 디지털 생존노트 제작 매뉴얼

2026-10-17 기준 · 오케스트레이터(AI)와 직원 에이전트가 쇼츠를 만드는 방법 전체

---

## 1. 채널 개요

| 항목 | 내용 |
|---|---|
| 채널명 | 디지털 생존노트 (@digitalsurvivalnote) |
| 한 줄 소개 | 디지털 사기에서 살아남는 법 |
| 다루는 것 | 보이스피싱 · 문자 사기 · 가짜 투자 광고 · 부업 사기 등 실제 사기 수법 |
| 형식 | 20~28초 동물 캐릭터 콩트. 평범한 이웃이 한마디로 사기꾼 여우를 받아치는 사이다 |
| 주 시청자 | 50~70대 본인, 그다음 부모가 걱정되는 30~40대 |
| 목표 | 구독자 1,000명 (10/23 중간 점검에서 목표일 재판정) |
| 운영 | 업로드만 사람(오너)이 YouTube Studio에서 직접. 나머지(기획·검증·대본·영상·분석)는 AI |

### 핵심 약속
"사기꾼이 지고, 우리는 살아남는다."
재미(웃음·사이다)가 주인공이고, 안전 행동은 사기꾼을 이기는 대사 한 줄로만 들어간다. 강의 장면은 없다.

## 2. 영상 형식

### 두 가지 시리즈
| 시리즈 | 내용 | 끝 |
|---|---|---|
| 진돗개네 역관광 (EP n) | 평범한 이웃이 사기 전화·문자를 한 수로 이긴다 | 이긴 사람의 의기양양한 얼굴 + 도장("역관광!" 등) |
| 여우의 영업비밀 (#n) | 사기꾼 여우가 속마음으로 수법을 자랑하다 망신당한다 | 당황한 여우 얼굴 + 도장("작전 실패", "뚝!" 등) |

### 25초 콩트 구조
1. **0초:** 바로 대사로 시작(훅). 화면 위쪽에 고정 상황 제목 2줄
2. **사기 수법 전개 (공식 자료의 순서 그대로):** 여우의 위험한 요구가 나오면 고슴도치 도치가 말없이 가시를 세움("삐빅")
3. **반전:** 주인공의 받아치는 한마디 = 공식 안전 행동 (예: "끊고, 은행 대표번호로 직접 걸게요.")
4. **도장 + 패자 클로즈업**
5. **마지막 1.5초:** "✔ 오늘도 생존 성공 / 부모님 단톡방에 공유해 주세요"
6. **끝 0.5초:** 첫 화면과 같은 장면으로 돌아가 반복 재생

### 시험 중인 장치
- 결말을 먼저 보여 주는 시작(콜드오픈): 도장 맞은 여우로 시작 → 되감기 → 본편
- 따옴표 대사 제목 vs 검색어 제목

### 하지 않는 것
- 강의·체크리스트·통계 카드 장면, 도치의 설명 대사
- 회차 점수 세기 (예: "3 : 0")
- 피해자 조롱, 지역·국적 말투 등 고정관념, 실명·실제 회사·로고

## 3. 제작 흐름 (직원 = AI 에이전트)

| 단계 | 담당 | 하는 일 | 결과물 |
|---|---|---|---|
| 1 | 레이더 (자동) | 해외·국내 쇼츠에서 뜨는 사기 소재 신호 수집 | 리포트 |
| 2 | 사실 조사 (fact-researcher) | 경찰청·금융위·금감원·소비자원 등 공식 원문으로 수법·숫자·안전 행동 확인 | 팩트시트 |
| 3 | 스토리 작가 (story-writer) | 팩트시트로 25초 콩트 대본. 필요한 인물을 정함 | 대본 JSON |
| 4 | 캐릭터 디자이너 (character-designer) | 이야기에 필요한 새 인물을 설계(종·색·나이 단서·옷·목소리) | 캐릭터 설정 파일 |
| 5 | 훅 편집자 (hook-editor) | 첫 2초, 상단 제목, 영상 제목, 대사 호흡 다듬기 | 수정된 대본 |
| 6 | 팩트체커 (fact-checker, 작가와 다른 에이전트) | 대사 한 줄씩 원문 대조, 안전 행동이 그 순간 안전한지 확인 | 검증 보고서 (승인/수정 후 승인/반려) |
| 7 | 오케스트레이터 | 수정 반영 → 최종 검토 → 사실 승인 기록 | 승인 기록 |
| 8 | 모션 디자이너 + 음성 연출 (motion-designer, voice-director) | 렌더링, 음성 품질 점검 | 영상 mp4, 썸네일 |
| 9 | 영상 QA (video-qa) | 화면·자막·소리·공개 표시 점검 | 확인 |
| 10 | 오너 | YouTube Studio 업로드 | 공개 영상 |
| 11 | 성장 분석 (growth-analyst) | 72시간 지표로 형식 판정 | 다음 편 방향 |

추가 직원: 스토리 분석가(story-analyst)는 해외 영상을 직접 보지 않는 작가를 위해 구조만 요약(클린룸), 시청자 패널은 필요할 때 30대·60대·20대 시청자 역할로 냉정하게 평가.

## 4. 사실 확인 규칙

- 수법의 단계와 순서, 숫자, 안전 행동은 공식 원문 그대로. 원문의 단정 수준("우려", "~할 수 있다")을 대사에서도 지킨다.
- 바꿔도 되는 것(각색): 인물 이름·나이·직업, 대사 말투, 장소, 시간 압축.
- 바꾸면 안 되는 것: 수법과 그 순서, 보도된 금액·날짜, 기관의 실제 조치, 공식 안전 행동, 결말을 실제 사건처럼 꾸미는 것.
- 기관명·날짜·통계·출처는 화면이 아니라 영상 설명란에 적는다.
- 승인은 팩트체커 검증과 최종 검토가 끝난 이야기만, 쓴 출처를 함께 기록한다.
- 업로드 직전에 해당 기관의 새 보도자료(경보 격상 등)가 있는지 다시 확인한다.

## 5. 대본 형식 (content/scripts/<날짜>-<이름>.json)

| 필드 | 뜻 |
|---|---|
| title / description / tags | 유튜브 제목·설명·태그. 설명란 첫 줄에 상황, 그다음 "실제 수법을 바탕으로 각색한 재연" 안내와 공식 출처 |
| disclaimer | "※ 실제 수법을 바탕으로 각색한 재연입니다" |
| hook_title | 상단 고정 제목, 2줄, 줄당 10자 안팎 |
| series / ep | 시리즈 칩 ("역관광" / "영업비밀", 회차 번호) |
| cast | 등장인물: voice(F1~F5, M1~M5), label(화면 이름), role(scammer / victim / inner = 속마음 등), character(캐릭터 등록 id), costume(여우 변장) |
| villain_set | 여우가 있는 장소 (콜센터, 가짜 사무실, 방송 스튜디오, 밤의 차 안, 세미나 무대) |
| scenes[].lines | 대사: speaker, text, face(표정), gesture(동작), spike(도치 경보), pause/speed(말 쉼·빠르기) |
| scenes[].twist / twist_on / twist_face | 반전 도장 글자, 클로즈업할 인물, 그 표정 |
| cold_open | 결말 먼저 보여 주기 (선택) |
| end_card | 마지막 문구 (기본: 오늘도 생존 성공 / 부모님 단톡방에 공유해 주세요) |
| sources | 공식 출처 목록 (승인 기록과 최소 하나 겹쳐야 제작 가능) |

점검 명령: `radar script-check <대본>` (오류 0이어야 제작)

## 6. 인물

- **인물은 이야기마다 새로 만든다.** 할아버지 경비원, 가게 사장님, 은행 창구 직원, 사회초년생, 이웃 아주머니 등.
- 캐릭터 한 명 = 설정 파일 하나 (content/characters/<id>.json): 종(개·여우·고양이·토끼·곰·너구리), 털색, 나이 단서(흰 눈썹·주름·안경·파마·모자), 옷·소품, 표정 습관, 추천 목소리.
- 그림 스타일: 2.7~3등신, 굵은 외곽선, 차분한 어른 색감(아동용으로 보이지 않게). 기존 캐릭터(카카오·라인프렌즈·주토피아 등)를 닮지 않게.
- **고정 악역은 사기꾼 여우 하나.** 수법마다 변장이 바뀌고, 변장은 항상 어딘가 샌다(귀·꼬리·수염이 삐져나옴): 후드티, 은행 정장, 수사관 코트, 택배 기사, 투자 고수, 부업 강사, 아들 얼굴 종이 가면.
- 도치(고슴도치)는 말하지 않는 위험 경보 마스코트. 채널 프로필 사진.

## 7. 음성

- 로컬 AI 음성(Supertonic 3), 속도 1.1. 대사 한 줄은 한 번에 합성(나눠 합성하면 끊김).
- 대사마다 세 번 합성해서 음성 인식으로 가장 또렷한 것을 자동 선택.
- 인물마다 목소리를 구분: 예) 여우 전화 M2, 여우 속마음 M5(낮고 음흉), 엄마 F3, 딸 F2, 아버지 M1. 목소리 복제 이야기에서는 가짜·진짜 아들이 같은 목소리.
- 대사 위에는 효과음을 깔지 않는다. 도치 "삐빅"은 대사가 끝난 뒤.
- 최종 음량 −14 LUFS 안팎, 배경음악은 곡마다 음량을 맞추고 대사 동안 낮춘다.

## 8. 화면 구성

- 1080×1920, 25~30fps, 자막 띠(화면 66~78% 높이)와 아래 20%, 오른쪽 버튼 열에는 얼굴·손을 두지 않는다.
- 첫 화면 = 썸네일. 얼굴 하나, 감정 하나, 얼굴이 화면 높이의 35~50%. 직전 편과 표정·소품·배경 중 둘 이상을 바꾼다.
- 공개 표시: 왼쪽 위 작은 "재연 · AI 음성" 칩(마지막 대사까지). 유튜브 업로드 때 "변경되거나 합성된 콘텐츠: 예".
- 컷은 1.5~2.5초마다, 강조 단어에서 화면을 확 당기고(펀치인), 놀라는 대사에서 흔들림.

## 9. 만드는 명령 (프로젝트 폴더)

```
radar script-check content/scripts/<id>.json
radar produce content/scripts/<id>.json --out media/final
python tools/upload_notepad.py        # 업로드 메모 media/upload/업로드_예정.txt
python tools/channel_stats.py         # 채널 숫자 기록
```
한 편 렌더링에 2~4분. 결과: media/final/<id>/video.mp4, thumb.png, meta.json.

## 10. 업로드 (오너, YouTube Studio)

1. 업로드 메모에서 그날 영상 파일·제목·설명·태그를 복사
2. 시청자층: **아동용 아님** · 변경되거나 합성된 콘텐츠: **예** · 공개 상태: 공개 · 시간: 19시 전후
3. 썸네일: 앱에서 맨 끝 장면 선택(첫 화면과 같음)
4. 고정 댓글: 받아치는 한마디 3줄 (링크·댓글 신청 유도 없음)
5. 올린 링크를 오케스트레이터에게 전달

## 11. 성과 판정

| 72시간 조회수 | 판정 |
|---|---|
| 5,000회 이상 | 그 형식 확대 (하루 1~2편) |
| 500~5,000회 | 첫 2초와 제목만 바꿔 재도전 |
| 500회 미만 + 시청함 50% 미만 | 그 형식 폐기 |
| 24시간 50회 미만 + 피드 노출 거의 없음 | 내용이 아니라 배포 문제로 보고 판정 보류 |

오너에게 받는 숫자: 조회수, 시청함 %(시청함 대 넘김), 평균 시청 시간, 구독 증가.
참고: 쇼츠 구독 전환은 대략 조회 1,000회당 1~2명이라 1,000명에는 누적 50만~100만 회가 필요.

## 12. 절대 하지 않는 것

- 남의 영상·음원을 내려받기·번역·더빙·짜깁기해서 올리기 (유튜브 재사용 정책, 2026-10 재업로드 노출 축소, 저작권 3회 경고 시 채널 삭제, 한국 저작권법상 번역은 허락 필요)
- 사실을 지어내거나, 각색을 실제 사건처럼 보이게 하기
- AI 음성·재연 표시 숨기기
- 브라우저나 프로그램으로 유튜브 업로드 자동화 (약관 위반)
- 실존 인물·회사·브랜드·제복·로고 사용
- API 키 등 비밀 정보를 파일·채팅에 남기기
